# Codex / BPS 双路径

账号编辑页提供两个独立开关：Codex 与 BPS。都开即 Codex + BPS，都关则不承接这两条路径的新请求；账号本身的启用、分组、权限和配额限制仍生效。单个编辑、批量编辑都在保存后生效。

两份主对话模型配置独立存储，支持完整模型 ID 或末尾 `*` 的前缀，例如 Codex 配置 `gpt-5.6-*`，BPS 配置 `gpt-6-*`。空列表表示没有额外限制，账号原有模型白名单仍然适用。新窗口的模型两边都匹配时优先 Codex。

单账号模型统一在「配置支持模型」弹窗中编辑，包含「账号白名单 / Codex / BPS」三个页签，使用模型标签添加和移除。三个页签一起保存，非法配置不会部分写入。探测和上游同步只作用于账号白名单；路径模型由管理员分别选择。账号编辑页只保留路径开关与模型配置入口，保存账号开关不会覆盖弹窗里刚更新的模型列表。

会话路径写入持久化窗口记录。已绑定的主会话可通过正式换号流程在 Codex 与 BPS 之间迁移，包括重新选中原账号。辅助请求跟随父窗口已提交的路径，不受主对话路径模型列表限制；已有的辅助请求模型授权设置仍然适用。

关闭当前路径或改模型导致原路径不再适用时，复用「禁用换号」设置与流程：

1. 未启用禁用换号或宽松模式时停止请求，不擅自迁移。
2. 路径关闭或不支持当前模型时，优先尝试原账号已开启、支持当前模型的另一条路径。
3. 原账号不可用时才按现有分组、权限、健康状态和窗口限制寻找其他账号。
4. BPS 原路径可用时继续使用 BPS；迁移候选不支持 BPS 时可选择其 Codex 路径。没有可用路径就明确报错，不绕过 Key 授权、账号健康或模型限制。

整号禁用、401、配额耗尽等限制不会因为 BPS 开关开启而被绕过。路径迁移同样使用现有上下文恢复设置；只有无法恢复的服务端引用时，仍可能需要补充历史或新建窗口。

同账号切换路径也会原子推进会话代次，重新生成出站会话和轮次 ID、重建缓存分区，窗口从 0 开始（47→0、48→1）。同一上下文的重试保持新编号；重启后恢复已提交的代次，不再次重置。旧代次不得更新新绑定或复用新代次的连接、Turn-State 和响应引用。

BPS→Codex 强制清理旧路径的加密压缩/推理、文件/输入项引用及不可复用的续链句柄，即使打开「完整保留 input」也不把这些字段带入 Codex。保留可用明文、工具声明及配对的工具调用/结果；清理后没有有效输入时需补充上下文。数据库只接受同时重建窗口、启用清理且不保留旧不透明输入的反向迁移。裸 BPS 引用仍不能直接路由到 Codex，只有已提交的新代次可在清理后发送。

原生 `/compact` 兼容转换只对实际走 Codex 的请求生效。BPS 保持原有压缩协议、`codex-auto-review` 到 Luna 的映射，以及 `max` 到 `xhigh` 的适配。管理员显式选择的测连路径继续允许独立测试；「按账号配置」根据测试模型选择实际路径。

本地诊断 `upstream_route` 记录路径、账号、代次；迁移诊断记录迁移前后路径及 `original_account_bps_attempted` / `original_account_native_attempted`。这些字段不加入上游正文或请求头。

旧配置缺少 `codex_native_enabled` 时，保持原有行为：原 BPS 账号仅开 BPS，其他账号仅开 Codex。第一次单独编辑 BPS 时会固定原来的 Codex 状态，避免另一个开关被隐式修改。配置支持导入、导出和重新加载。

批量设置模型同样提供账号白名单、Codex、BPS 三个页签。每个列表必须明确选择“批量修改”后才会提交，可以同时保存多个列表；未选列表不变，选中的空列表清除对应限制，路径开关不受影响。`POST /accounts/batch-models` 接受可选的 `models`、`codex_native_models`、`codex_bps_models` 数组，至少提供一个；先验证全部列表，再对每个适用账号统一保存。
