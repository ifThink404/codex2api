# 账号探测与 API 错误恢复

账号的后台探测与正常业务请求是两条独立路径。没有探测记录、探测关闭或记录过期，不等于账号不可用；调度仍须结合实际请求结果、手动暂停、额度和当前冷却判断。

账号编辑／调度配置支持以下字段，单账号与批量更新均走现有管理接口：

| 字段 | 默认值 | 含义 |
|---|---|---|
| `probe_mode` | `auto` | `auto`：API Key 账号不主动进行后台连通性探测，OAuth 保留原有探测策略；`off`：关闭后台用量、连通性与恢复探测；`on`：开启该账号对应协议的后台探测。 |
| `probe_interval_minutes` | `0` | `0` 沿用系统间隔；`1`–`1440` 为账号级最小探测间隔。失败尝试同样受间隔约束，避免每轮巡检重复请求。 |
| `api_auto_recovery_enabled` | `false` | API Key 账号的错误自动恢复，独立于探测开关。开启后，临时上游鉴权／拒绝错误进入短时退避，冷却结束后由正常请求验证恢复。关闭时保留原来的错误处理方式。OAuth 不适用此开关。 |

这些配置存储在现有账号 credentials JSON 中，通过 PostgreSQL 的账号更新与投影链路持久化；无须新增表或修改数据库引擎。未配置新字段的账号使用上表默认值。

## API 错误自动恢复

中转 API 的上游可能又是一个 OAuth 池。该池返回 `401`、`403` 或 `auth_unavailable`，并不一定表示 codex2api 保存的中转 API Key 已失效。开启自动恢复后，适用的 `401/403` 不再触发 Codex OAuth 的永久封禁层或自动删号，而进入 15 秒起、最多 5 分钟的退避。冷却结束后，正常请求可以重新被分配；成功后清除已到期的临时错误。

这一开关不会将失败响应伪装为成功，也不能修复中转上游自身的账号池故障。Grok 明确的永久权限拒绝、明确额度／账单限制、手动暂停和终态错误仍按各自规则处理。旧的并发请求成功不会抹掉仍生效的新冷却。

在临时冷却尚未确认恢复时关闭自动恢复，会取消自动恢复计时并恢复原来的鉴权隔离规则；管理员仍可通过手动测试或更新凭据恢复账号。更换凭据不会继承旧凭据的临时冷却。

账号页会单独显示“上游暂不可用”等状态。`payment_required` 显示为“上游拒绝／账单限制”，因为旧版本也会把部分 HTTP 403 映射到该状态，不能仅凭标签断定余额不足。历史成功率与当前冷却是不同指标；API 中转账号不适用官方 OAuth 的 turn-state 观测，不展示“未记录”来暗示异常。

后台探测关闭时仍可使用手动“测试”。OAuth 令牌续期以及供应商必要的账单、模型目录等控制面同步与本开关分离，避免关闭探测后令牌自然过期。

Turn-state 模板的后台续期会发送推理请求，因此也遵守账号探测开关和最小间隔；失败尝试同样占用间隔。关闭探测后不再发起新的模板获取或验证请求，手动刷新模板仍可用。

## 排查时区分两层故障

- codex2api 选号失败：检查账号启用状态、分组、并发、冷却及会话粘性。
- 已请求中转，但中转返回 `auth_unavailable: no auth available`：该错误来自中转内部账号池，应检查中转的凭据与恢复机制。解除 codex2api 的错误隔离只能允许再次尝试，不能保证中转返回成功。

建议先在目标 API 账号开启自动恢复并关闭后台探测，观察真实请求；需要主动健康检查时，再为该账号单独开启探测并选择间隔。其他账号可保持原配置。
