# 使用日志 Turn-State 列

使用日志单独展示本次请求真实 `X-Codex-Turn-State` 的字符数：优先采用本次上游尝试首次返回的非空值，没有返回值时采用本次实际出站值。支持点击该列快速筛选，也支持通过下拉框和字符数输入框筛选。长度不代表状态等级或模型能力。

- `292 字符` 等正数：本次有真实值，直接显示字符数，不区分新返回或已使用。悬停显示字符数以及可正常 Base64 解码时的字节数，例如 292 字符可能对应 217 字节。
- `未获取 · 0 字符`：本次没有采集到上游返回值或实际出站值。旧日志保持当时仅统计上游返回的口径，不回填。
- `未记录`：历史日志或请求未完成采集，例如在发送前就失败。不能推断为没有携带该字段。

返回值支持 HTTP 响应头和 WS 转换后的 SSE metadata 事件；出站值在最终 HTTP 头/请求体或当前 WS 帧上采集，并要求本次尝试已完成发送。出站数值摘要保存在 `upstream.request_turn_state`，不依赖可能被裁剪的身份快照。HTTP 头优先于请求体，不使用复用连接的旧握手头，也不直接使用客户端代号或尚未出站的恢复记录。切号清理后的空值不会带入旧号的长度。映射保存失败时仍记录已观察到的真实返回值长度。每次选号尝试独立记录，旧流的迟到事件不会污染新尝试。

日志写入两个可空整数 `turn_state_length`、`turn_state_decoded_bytes`，列表与导出共用筛选条件：`turn_state=received|missing|not_recorded`，以及精确匹配 `turn_state_length=N`。默认全部。筛选在数据库分页前进行，不逐条请求诊断详情，不扫描 JSON 提取字段，也不回填旧日志。

API 中转同样支持受当前账号、用户、线程和轮次约束的 Turn-State 代号恢复，已验证的状态头不依赖身份头透传开关。诊断分别记录 `upstream.request_turn_state` 和 `upstream.response_turn_state` 的字符数，区分实际发送与实际返回；上游没有提供状态时保持为空，不生成替代的上游状态。响应代号仍由网关签发，原始上游值不回传给用户。

PostgreSQL 的长度/时间索引随现有后台索引任务在线创建；SQLite 沿用现有迁移机制。新增列不发起探测、不改变上游请求、响应时序或代号映射策略。

账号页的健康条和套餐标签悬停会显示「最近请求 Turn-State：292 字符」。该值随现有 `/accounts/health-bars?ids=...` 接口的 `latest_requests` 返回，直接读取当前页各账号最近一条保留日志的长度列；不取最大值、不跳过零值或未记录值寻找更早的数据，也不受健康条 200 分钟统计窗口限制。内部测试和网关续写日志不参与选择，同一时间的记录按日志 ID 取最新。没有请求记录的账号不显示这一行。

最新请求查询只接受当前页范围（最多 500 个去重账号），空选择和全池超限选择不执行额外查询。使用既有 `(account_id, created_at)` 索引，每个账号 `LIMIT 1`，通过一条批量 SQL 返回结果；悬停仅渲染本地数据，不新增 HTTP 请求，不解析诊断 JSON。表格、卡片和账号详情共用这一显示。
