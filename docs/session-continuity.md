# 主会话连续性与原账号保护

管理员入口：提示词防护 → 风险控制 → **会话连续性校验（测试）**。保存后生效，旧配置默认 `observe`。

## 测试模式

- `off`：不因窗口序号异常直接拒绝；遇到 `window_gap` 或 `unbound_nonzero` 时自动重建出站会话，从 0 编号，仍维护原账号与原始入站序号基线。
- `observe`：记录 `would_block` 与原因，但不因序号异常拦截。建议先运行此模式，检查使用统计中的请求诊断。
- `enforce`：按以下规则拒绝异常主请求，HTTP 返回 400，WS 返回对应错误帧。开启前需在管理界面再次确认。

该模式不关闭身份签名验证、原账号保护、模型限制或收费授权。身份/账号归属冲突、无法安全读取归属仍会停止请求。原账号容量不足时，只有另行开启账号自动换号且通过候选、上下文及窗口授权校验才可迁移，不能通过切换观察模式绕过。

### Responses API 中转账号

管理台标记为 API 的 `openai_responses` 中转账号不适用 Codex 主会话连续性、根账号等待、fork 继承、账号级 ID 映射、用户会话窗口准入及会话黑名单保护。按已鉴权 Key 的分组、套餐、账号白名单和模型范围确认 API 路由后，使用独立本地软粘性命名空间，不复用旧 Codex 持久归属，不记录新的 Codex 连续性基线。入站 ID 不因本地路由命名空间而改变。

API 独立路由或已有 API 归属直接豁免；混合池中，已有 Codex 归属继续受保护，正常新请求保持原调度。没有可确认归属且会被 Codex 非零窗口、压缩或后台/fork 根要求拦截时，可限定到授权范围内的 API 账号。进入豁免路径后，最终账号过滤必须保持 API-only；API 不可用也不能回退到未经过保护的 Codex 账号。诊断 `api_relay_session_exempt=true` 和窗口结果 `api_relay_exempt` 表示此路径。

窗口预检没有模型路由信息，因此使用更严格的范围判断：已通过 API Key 鉴权，且该 Key 按账号白名单、分组、套餐和渠道权限可访问的账号全部为 Responses API 中转时，`/v1/session-windows` 的 `quote`、`quote_tiered`、`list` 直接返回 `ordinary_only`、空票据和空窗口列表，不要求 NewAPI 用户签名，也不读取或修改用户窗口。不依据 Key 名称或客户端豁免头判断；临时不可用的 Codex 账号仍计入授权范围。混合池、未知账号范围及升级/释放操作继续验证 NewAPI 身份。NewAPI 可使用已有的 `ordinary_only` 处理，无需额外升级。

仍执行下游鉴权及 NewAPI 签名、账号分组权限、模型支持、预算/RPM/并发、内容防护和不透明响应/压缩上下文的来源校验。上游 API 或 NewAPI 自身返回的限制不会被网关清除。原生下游 WebSocket 端点目前仅调度 Codex 账号，本次不增加 API WebSocket 桥接能力，也不放宽该端点的 Codex 保护。

| 已记录状态 → 当前主请求 | 处理 |
| --- | --- |
| 无归属 → 普通主请求 `T:0` | 允许首次选号，准入后保存归属 |
| 无归属 → 主会话压缩（包括 `T:0` 和非零窗口） | `sever` 允许首次选号并建立当前窗口基线，保留完整输入，不触发丢弃历史的重建；已有账号绑定仍优先复用 |
| 无归属 → `T:11` | `unbound_nonzero`；关闭模式重建出站会话，观察模式仅记录，正式模式拒绝 |
| 新 fork 无自身归属，显式父会话可核实 → `T:27` | 先按原始父身份恢复账号，再为 fork 建立独立序号基线；不继承父窗口收费授权 |
| 有归属但无序号记录 → `T:71` | 首次建立基线，继续原账号，不把旧窗口当作新窗口 |
| `T:71` → 主请求/压缩 `T:71` | 复用原账号 |
| `T:71` → 主请求 `T:72` | 正常推进，不创建新账号绑定 |
| 跳号 | `window_gap`；关闭模式重建出站会话，观察模式仅记录，正式模式拒绝 |
| 线程不一致 | 记录具体原因；仅正式模式按序号拒绝，不自动重建 |
| 同账号、同原始线程的序号回退 | 持久归属核实一致时允许，仍记录 `window_regressed`；不放宽归属或身份冲突 |
| 缺失或矛盾的窗口字段 | 不假定为 0，不用矛盾值推进基线 |

解析原始请求的 `thread_id:window_number`，并核对元数据中的 `window_number`（如果存在）。WS 只使用当前帧字段，不拿升级握手或上一次帧的窗口序号补空。不改变发往上游的既有字段收敛、时区改写和签名处理。

新普通 fork 在非零窗口校验前查询父会话原始身份对应的持久账号归属；没有持久记录时才查询有效运行期绑定。持久归属优先于旧内存绑定，不将父会话的序号、切换代次或窗口授权复制到子会话。查询受原请求的用户/API key 范围约束，仍检查父系黑名单、账号模型支持和子会话独立容量准入。默认在显式父归属无法确认时返回 `codex_session_continuity_fork_owner_unavailable`（400）；可另行开启下面的宽松模式。压缩不能借 fork 标记绕过原账号恢复要求。

压缩请求使用它携带的当前序号，不在压缩开始时预增。基线记录“已准入的最高有效序号”，不是直接用最后完成的请求覆盖：较旧请求晚结束不会回退基线。序号表示客户端上下文的推进线索，不是用户消息轮数；非零本身也不能证明请求来自旧设备或伪造客户端。参考 [官方 Codex 仓库](https://github.com/openai/codex)。

Codex 恢复旧历史/回滚时可能恢复较小的窗口序号。同一已验证用户、根、完整原始线程和账号归属内允许此类回退；子线程仍不推进主线程基线。换号后的编号不再直接相减，而按原始线程及 `context_window_id` 持久化分配。例如 `16/X→0`、回退 `15/Y→1`、重试 `15/Y→1`、新上下文 `16/Z→2`、恢复 `16/X→0`。不会出现 -1，也不会将不同上下文强行压到 0。没有上下文 UUID 时按原始序号匹配；同号存在多个已知上下文时必须提供 UUID，不能猜测。

稳定主会话的压缩先恢复持久归属、已有账号绑定或已验证窗口授权中的原账号；找不到时返回 HTTP 400 / WS 错误帧 `codex_session_continuity_unbound_compaction`，附带 `retry: stop`。不等待固定时长，不从最近账号或候选池另行选号，也不写入新的归属。该规则不受 `off` / `observe` / `enforce` 序号测试模式影响。覆盖 `/v1/responses/compact`、`/v1/responses` 中的 `compaction_trigger` 与规范元数据 `request_kind=compaction`；WS 使用当前帧，不用旧握手的压缩标记判断当前轮。仅携带历史压缩结果的普通请求不因此被当成新的压缩操作，元数据标记也不会把 `/responses` 请求改路由到 `/compact`。

## 宽松模式

管理员入口：系统设置 → 全局用量自动暂停阈值 → **宽松模式**（在账号自动换号开关下方）。为兼容已有配置，沿用字段 `codex_fork_account_fallback_enabled`，默认关闭，保存后生效。独立于普通会话的账号自动换号开关和连续性校验模式。

宽松模式下，首次选号、已有绑定恢复、重试和换号均不按分组筛选：忽略 API Key 的允许账号分组、主组／分流组路由和新旧账号分组完全一致要求。未分组、仅部分重叠或完全不同分组的账号都可成为候选。保存的分组配置不会被删除，关闭宽松模式后恢复生效；切换时会使旧的分组候选池缓存失效。显式账号/API Key 绑定、套餐、渠道、模型、账号状态、预算、并发、容量、窗口授权、上下文和 BPS 路径下限继续校验。日志以 `group_routing.reason=relaxed_no_groups` 和 `account_failover.selection.match_mode=relaxed_no_groups` 标明此行为。

对于尚无自身账号归属、携带有效父身份及窗口字段的普通用户 fork：

- 父账号能够接纳新会话时，仍优先继承父账号。
- 父账号的会话容量已满，允许按正常候选规则重新选号。
- 父会话没有持久或有效运行期归属，或归属账号已被删除，允许独立选号。数据库读取失败仍停止，不能当作“找不到”。
- 已有自身绑定的 fork 和普通主会话压缩不适用。请求并发占满或父账号不支持模型本身也不触发重新选号。

对于被动/后台请求（标题、建议、审核、记忆整理、子智能体等），如果无法定位父会话，或父会话绑定的账号已删除，允许按候选规则临时选择可用的 Codex/BPS 账号。使用独立的请求级容量键和出站身份段；正常占用目标账号容量及并发，请求结束后释放。不会创建或改写父会话的持久账号归属、用户窗口或窗口票据，也不借用父账号的额外后台并发。后续请求重新检查父会话；若父会话已经出现，恢复跟随父账号。临时请求之间不承诺复用账号或上游续写句柄。

已存在的父账号额度耗尽（含 5h/7d 和用量阈值自动暂停）、手动暂停、禁用，或无法接纳当前会话时，也允许被动请求临时选择其他账号，并保留父会话原绑定。已有根窗口能够复用时，不会仅因其他窗口占满而换号；模型命中账号级额度豁免且父账号仍可用时继续跟随。临时请求排除原父账号，避免选回失效身份。数据库故障、入站身份字段互相矛盾、黑名单和已有窗口授权继续按原规则处理。模型豁免仍由原被动请求权限及开关控制。临时出站上下文沿用完整保留 input 设置；无法安全重建工具上下文或只剩不可复用引用时停止。诊断 `relaxed_account_fallback` 记录原因、临时账号和上下文清理情况。

账号级出站模式下，原始会话 ID 已由其他归属登记时，宽松模式允许按当前用户与目标账号生成独立出站映射，并登记映射后的 ID。适用于普通请求和子任务，也兼容从未签名共享 Key 切换到签名用户后的旧登记；不会转移或覆盖旧用户的登记。首次映射持久保存，重试继续复用。无法完整映射、持久存储不可用或显式使用 preserve 模式时仍停止；关闭宽松模式恢复原有冲突检查。管理员日志的 `upstream.identity_claim` 记录 `result`（`claimed` / `conflict` / `isolated` / `isolation_failed` / `isolation_incomplete`）、当前归属来源、当前/历史归属哈希和冲突键哈希，不记录凭据。

新 fork 的 `quote` / `quote_tiered` 预检保留未绑定的窗口票据，正式请求再优先检查父账号，避免预检把它提前锁定到父账号。个人窗口额度、扩容计费授权、账号白名单、模型权限及父系黑名单仍生效；已知 BPS 来源只选 BPS，不回流 Codex，也不通过此开关切换到 API 中转账号。

重新选号成功后，仅为 fork 建立独立持久归属和出站身份，出站窗口从 0 起；父会话归属保持不变。原父引用只从出站请求头和元数据中移除，本地入站身份、父子关系和日志追踪保留。后续请求、进程重启及关闭开关后继续使用 fork 已建立的绑定。

上下文按“切号时完整保留 input”设置处理，并随新出站段持久化：默认清理旧账号不可复用的响应引用、加密上下文及 turn-state，保留可用明文和工具；完整保留模式沿用其既有校验。默认清理可能丢失加密历史，清理后无可用输入时返回 `codex_session_restart_context_required`，不创建绑定。

诊断 `session_continuity.fork_account_fallback` 记录 `reason`、已知的 `parent_account_id` 和 `preserve_input`；原因分别为 `fork_parent_capacity_full` / `fork_parent_missing`。提交前为 `action=restart_pending`，成功后为 `action=restarted`。持久记录使用 `continuity_` 前缀区分重建原因，同一 fork 的并发选号通过数据库原子校验只能提交一个账号。

## 关闭校验时自动重建出站会话

仅针对 `codex_session_continuity_window_gap` 和 `codex_session_continuity_unbound_nonzero` 两种情况。窗口准入成功后，持久化新的出站身份代次，复用切号时的会话、线程、轮次与上下文窗口 ID 映射，并建立新的 WS 连接。例如异常请求及后续请求 `47 → 47 → 48` 发往上游时为 `0 → 0 → 1`；再次跳到 `55` 时另建出站会话，从 0 开始。正常重试和连续推进不会反复重建，映射保存到数据库，进程重启后可恢复。

这里只重建出站上下文，不主动更换已有绑定账号，不重置用户窗口的价格授权或到期时间。没有归属的新请求仍按正常规则选号。入站身份与原始序号保留用于归属和诊断；观察与正式拦截模式保持各自行为。

上下文清理与切号一致：清除旧会话的响应引用、轮次状态及不可复用的加密上下文，保留可用的文本输入。只有旧引用或加密数据、清理后没有可用输入时，返回 `codex_session_restart_context_required`，要求补充当前问题及必要资料，不提交重建。新出站会话内已验证的上下文仍可继续复用。缺失或矛盾的窗口字段、无归属的压缩请求、身份及账号归属冲突不会通过此机制绕过原有检查。

诊断保留触发原因 `window_gap` / `unbound_nonzero`，提交前 `action=restart_pending`，成功后 `action=restarted`；持久记录中的重建原因为 `continuity_window_gap` / `continuity_unbound_nonzero`，用于区分账号切换。

## 保号与扩容

已识别为 `thread_source=user` 的稳定主链路（包括拥有主根的压缩请求）维护持久归属。来源字段缺失但已解析出稳定根身份的非关联请求也维护同样的持久归属，不能因为只携带 Session-Id 或后续丢失 thread_source 而退回可换号的普通临时粘性。不将其改标为官方主请求，也不授予被动权限；已知后台、子智能体、关联请求以及无法解析或冲突的根身份不因此获得独立主账号。后台关联与等待策略保持不变。

账号会话槽闲置释放与账号归属分离：释放槽不等于遗忘原账号。主请求在启动/重连后可从持久记录或已确认窗口授权恢复原账号。候选重试、压缩偏好、fork 继承均不能越过已恢复的原账号；不支持所选模型仍提示新开对话，不改投其他账号。

这是持久硬绑定，不是提高调度权重。已保存的根账号归属不设 TTL，不因间隔两小时、计费窗口到期、模型切换或进程重启重新选号；序号测试模式为 `off` 或 `observe` 时也不解除账号归属。原账号支持新模型时仍用原账号，不支持则返回 `session_model_unavailable`；账号不可用时默认停止请求，另行开启账号自动换号后才允许按受限迁移流程处理。上述保证依赖同一根身份和归属数据仍然存在：旧版本已经丢失或改写的历史归属不会从使用日志自动重建，新开对话才按首次选号规则处理。

例如将临时粘性 TTL 配置为 20h，21 小时后同一根请求携带 `T:0`，仍先查询持久归属并使用原账号，不因序号为 0 就再次选号。TTL 到期不自动加入管理员黑名单；账号恢复后允许原会话继续请求。只有没有任何可恢复归属的新身份才进入首次选号规则，不能仅凭 `:0` 证明它历史上从未使用过。

持久原账号已禁用、暂停、额度耗尽或被本次请求排除时，候选等待也只检查原账号，不会因为池里还有其他可用账号就空等它们；正常并发排队仍等待原账号释放资源。

同请求重试复用自己的有效 API Key scope 并发占位，不会被自己占用的位挡住；其他请求、已释放或已过期的占位仍按原并发上限判断。账号绑定本身不授予额度续链豁免，只有原本符合续链条件的请求保留该语义。

未开启账号自动换号时，普通槽不足且未授权扩容的已有普通窗口返回 `codex_sticky_expansion_required`；普通和保留槽均满返回 `codex_sticky_account_capacity_full`。开启后，有持久归属的主请求可因容量不足尝试迁移到账号分组集合完全一致（标签不参与）、模型权限和容量均满足的账号。NewAPI 报价预检不再仅因原账号容量满而强制扩容，实际选号、上下文清理和授权迁移在正式请求中完成；个人窗口限额仍正常执行。具体迁移约束见 `codex-outbound-session.md`。同账号并发、暂停、额度、模型等限制仍生效，保留槽不绕过这些约束。

NewAPI 的个人窗口页提供单窗口确认：先开启扩容，再确认该窗口后续请求的新倍率。控制端只信任经签名的用户身份和管理员策略，不接受客户端指定上游账号。预占原账号保留槽，提交新价格版本后才能放行；失败回滚临时占位。保留原创建时间和到期时间，占一份个人扩容额度，历史与已授权在途请求不追溯加价。旧价格授权再次使用会返回 `window_billing_refresh_required`，由 NewAPI 在转发前重新授权和重算预扣。

## 诊断与性能

使用统计 → 请求诊断 → 会话连续性校验，包含 `mode`、`result`、`action`、`would_block`、原始 `thread_id`、前后序号、原账号及归属来源。拒绝在选号前发生时也记录诊断。

使用日志的模型下方显示窗口序号标签：绿色表示未改写，悬停显示原序号；橙色显示改写后的序号，悬停显示“原序号 → 出站序号”。序号从当前请求及出站正文/HTTP 请求头采集，不使用复用 WS 连接的旧握手序号。两个序号以轻量字段保存，列表无需加载完整诊断；历史记录未采集这些字段或无法确认序号时不显示标签。

新增 `codex_session_continuity` 表按根键精确读写，不扫描历史用量。首次绑定或有效序号推进持久化；普通同序号请求命中内存，活跃时间写入最多每根 5 分钟一次。归属缓存和价格缓存各限制 32768 项。窗口列表仍按用户查询，并使用 NewAPI 原有短缓存与合并查询；单窗口升级只在用户确认时请求控制端。持久归属不随槽位 TTL 删除，存储随历史根数增长；运维清理该表会失去对应根的重启恢复能力。

先部署 Codex2API，再部署 NewAPI。仍需保证同一上游账号由同一调度进程管理或使用粘性路由；本功能不是跨独立调度器的分布式账号锁，也不承诺跨独立进程的即时价格缓存同步。回滚旧 Codex2API 前先停止单窗口升级入口并排空旧价格授权，避免旧版本不识别升级后的价格版本。

回归覆盖：三种模式、配置保存、HTTP/WS 非零初始窗口拦截、旧握手与当前帧分离、`71 → 压缩71 → 72`、缺字段基线、重启恢复、禁止改投其他账号、扩容额度与保留位不足、占位失败回滚、旧价格票刷新和在途价格快照。
