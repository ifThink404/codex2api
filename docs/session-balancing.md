# 新会话均衡

设置页的“新会话均衡”提供三个互斥选项，设置后立即生效，支持设置导入导出。

| 选项 | 新请求需要选号时的行为 |
| --- | --- |
| 默认 | 沿用当前调度模式、亲和散列设置。 |
| 窗口 | 在同优先级、同健康档位内，依次比较占用槽数、正在执行的请求数、活跃会话数，优先选较少者。占用槽包含缓冲保留槽。 |
| 会话 | 在同优先级、同健康档位内，依次比较活跃会话数、占用槽数、正在执行的请求数，优先选较少者。 |

负载相同时再比较调度健康分，最后沿用散列或调度游标打散。索引调度、旧版扫描和影子模式使用相同的负载比较规则；索引模式只在需要新选号时比较候选层的负载，默认模式和已绑定请求不增加这项扫描。

已有会话继续遵守原有粘性、续链和账号归属规则。均衡不会为拉平统计而迁移可用的已绑定账号，所以开启后不会立刻消除旧会话造成的负载差异。禁用、暂停、冷却、账号范围、请求过滤器和容量限制仍生效。

会话数优先使用账号会话容量功能的未过期记录；未开启该功能的账号使用有效的普通亲和绑定计数，不把后台派生请求重复计成新会话。没有会话标识的请求可按当前负载选号，但不会虚构新的会话记录。单个进程内，新选号的比较、占槽和会话准入顺序执行，避免同时进入的新请求都依据同一旧负载选中一个账号；不同实例间不承诺全局实时最小负载。

API 字段为 `session_balance_mode`，取值 `default` / `window` / `session`。旧字段 `session_window_balance_enabled` 继续兼容；迁移旧配置时，关闭对应“默认”，开启对应“会话”。同时提交两个字段时，新字段优先。新安装默认选择“默认”。
