# 额度耗尽后允许指定模型

账号编辑的调度设置提供 **额度耗尽后允许指定模型**，新建普通 Codex 账号默认开启，名单为 `gpt-5.6-sol`。已有账号保留原配置；导入文件中的显式关闭和空名单也会保留。管理员需填写完整模型 ID，不支持通配符；空名单不豁免任何模型。批量编辑用“修改 Codex / BPS 调度设置”总开关统一应用整组设置，关闭时保留各账号原配置。

配置保存在账号凭据的非敏感字段：

```json
{
  "codex_usage_limit_bypass_enabled": true,
  "codex_usage_limit_bypass_models": ["gpt-5.6-sol"]
}
```

单账号及批量调度更新接口均支持这两个字段；省略字段保留原值，`false` 关闭，`[]` 清空名单。配置支持数据库恢复、调度实例同步及账号导入导出，仅适用于 Codex 账号（包括实际使用 BPS 的账号）。混合渠道批量修改会在写入前拒绝不支持的账号。

名单按本次请求经过模型映射后的模型名称匹配，不替换请求模型。匹配时跳过本地 Codex 主额度 5h / 7d 耗尽、对应窗口冷却和用量阈值自动暂停；新请求、粘性请求、续传、HTTP 和 WebSocket 使用相同规则，不会因为该额度状态主动切走已绑定账号。名单外模型沿用原策略。Spark 的独立额度不在豁免范围内。

账号错误、鉴权失败、封禁、手动禁用/暂停、真实请求限流及过载冷却继续生效；API Key 权限、分组、模型白名单、Codex/BPS 路径配置、请求并发和会话容量也仍需满足。此设置不增加官方额度，上游实际拒绝时仍返回其错误。用量百分比、重置时间和限流状态继续如实显示。

新的本地 7d 冷却使用 `rate_limited_7d` 标记；旧 `rate_limited` 记录仍通过重置时间匹配识别，无法确认是本地窗口冷却时不会猜测放行。能够继续服务名单模型的账号不会被额度耗尽自动清理，管理员仍可明确删除账号。

批量编辑中的旧“两条路径模型配置”文本框已移除。Codex / BPS 路径模型继续使用独立的批量编辑模型入口，此改动不清空任何已保存模型列表。
