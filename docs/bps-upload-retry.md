# BPS 附件上传失败与后台重试

当前默认先尝试 [账号级两小时附件回退](bps-attachment-429-fallback.md)。下面的失败重试流程适用于未被回退接管的错误，或显式设置 `CODEX_BPS_ATTACHMENT_429_FALLBACK=off` 的部署。成功就地回退时，不记录一次失败推理或触发附件上传换号。

适用于失败阶段为 `bps_image_preparation` / `bps_file_preparation`、且 `inference_attempts=0` 的请求：附件准备失败发生在模型推理之前。

附件上传的 HTTP 429 使用独立的「429 重试次数」，不消耗普通重试次数。即使普通重试为 0、持续重试关闭，只要 429 重试预算仍可用，宽松模式也可按现有账号资格及会话迁移检查换号。旧窗口在本实例首次选号后上传失败、以及已有绑定的窗口均适用。其他上传错误继续使用原有普通重试规则；参数、策略及取消检查不会被绕过。

上传接口明确返回 HTTP 429 后，还会记录独立的账号附件上传冷却：优先使用有效的正数或 HTTP 日期 `Retry-After`，缺失／无效时为 60 秒，上限为 5 分钟。该状态不等于模型额度耗尽，不修改账号全局健康度；有共享运行态缓存时跨实例共享，缓存故障时保留本地观测。相同上游账号的重复账号记录使用同一个冷却键。成功的文字推理不清除尚未到期的上传冷却。

后续请求在首次选号、重试选号和会话迁移时均检查上传冷却；仅影响仍需上传内联图片／文件的 BPS 请求，原生路径、纯文字、已有文件引用和命中可用附件缓存的请求不受影响。宽松模式下，旧窗口会在发送前通过现有原子迁移流程选择 Key 授权范围内的可用账号，避免每次先在已知失败账号上重新上传。已验证的后台派生请求使用临时账号，不移动父会话。冷却到期后恢复正常资格。

如果旧绑定处于上传冷却且没有合格替代账号，保留原绑定和会话代次，返回可重试的 503，并发送 `X-Should-Retry: true`，使响应头与正文的重试提示一致；这是发送前的调度失败，不伪造新的上游上传尝试。当前请求已经收到的实际上传 429 仍保留原有错误响应。诊断中的 `bps_upload_cooldown` 区分上传冷却与模型限流，`upload_primary_error.retry_after` 保留经验证的上游重试提示。

Responses、Compact、Chat Completions、Messages 和 Responses WebSocket 入口会为每次附件上传失败记录一条使用日志，包含账号、请求 ID、尝试序号和脱敏上传诊断，错误类型为 `bps_attachment_upload`。失败发生在推理前，因此不填充 token 用量或推理费用；重试成功另记成功尝试。这类上游失败不重复写入服务错误日志。

宽松模式开启时，已验证的后台派生请求在父账号发生可重试故障、被本次请求排除后，可以使用独立的临时绑定选择其他合格账号。父会话账号、换号代次和窗口不会被改写。请求结束时释放临时绑定。重试次数和请求截止时间沿用原设置；暂停、禁用、权限范围及模型限制仍生效。普通硬排除、参数错误、明确的策略拒绝、已取消请求和显式窗口授权票据不会触发这个兜底。

未启用宽松模式时保留父账号归属，但不再为本轮已排除的父账号额外空等 30 秒；后续仍由原有重试/终止策略决定。候选池耗尽且最后一个实际错误是附件上传失败时，HTTP/SSE/WebSocket 保留该失败及对应状态，不再统一改成 400“无可用账号”。

宽松模式下上传重试可在 Key 授权范围内跨组换号，不要求新旧账号分组一致，也不固定主组／分流组路由。Key 分组权限、其他账号资格及 BPS 路径限制仍生效；授权范围外的账号不能作为重试目标。若仍无候选，服务错误日志保存最终选号结果（`codex_dispatch_bps_upload_retry_unavailable`），与每次实际上传失败的使用日志分开记录，便于判断是目标不可用还是换号后再次限流。

诊断位于 `upstream.bps_compat.timing`：

- `upload_primary_error`：首个有效上传错误，含阶段、实际 HTTP 状态、错误码/类型、脱敏说明、上游请求 ID 和 CF-Ray；同批上传取消不能覆盖它。
- `upload_errors`：最多 8 条错误样本；`upload_errors_omitted` 记录未展示数量。
- `upload_canceled`：取消数量。`upload_failures` 仍包含取消，不能把所有失败计数都解释成上游 HTTP 拒绝。
- `upload_last_http_status`：最近观察到的非零 HTTP 状态；状态为 0 的网络失败/取消不再覆盖此前状态。定位根因优先看 `upload_primary_error`。

`stage` 区分 `http`、`transport`、`response_read`、`response_shape` 和 `canceled`。没有收到 HTTP 响应时，诊断不伪造上游状态码；客户端仍可能收到网关生成的 502。日志仅保留有界的结构化错误字段，清理已知凭据、文件名和附件 ID，不记录文件正文或完整响应正文。
