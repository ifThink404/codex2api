# sever 会话换号检查与重构（2026-09-26）

本次检查覆盖请求准备、持久归属恢复、主会话选号、模型约束、请求内重试、fork、后台临时请求、候选筛选、身份准备、窗口授权及归属事务提交。以下清单区分错误阻断、管理员策略和必须保留的校验，不表示可以保证真实上游永远接受重放。

## 修复的阻断点

| 原因 | 原行为 | 现在的行为与实现 |
| --- | --- | --- |
| 原账号没有请求的模型 | `CheckSessionModel` 直接拒绝，忽略自动换号 | 先使用无副作用的模型检查，允许正常迁移；关闭换号时保留原提示。`session_failover_policy.go`、`auth/session_model_affinity.go` |
| 宽松模式触发白名单不全 | 401、凭据缺失、错误/封禁、路径关闭等未触发 | 两种开启方式共用账号故障原因目录，避免入口各维护不同白名单 |
| 普通冷却、模型冷却 | 调度器拒绝账号，迁移层仍认为账号健康 | 复用调度器的本地及共享缓存冷却、Key 授权、出口、调度次数判断。`auth.SessionDispatchFailure` |
| Spark、额度豁免、延迟刷新 | 容易被独立判断误认为不可用 | 保留按实际 dispatch policy 的额度豁免及 lazy refresh；不豁免真实鉴权/服务器故障 |
| fork / 后台入口独立白名单 | 只认缺失、额度或容量，忽略其他账号故障 | 共用 `sessionOwnerFailure`；后台仍用临时键，不能改写父会话归属 |
| 已观察到的可重试排除 | 普通自动换号模式只认额度耗尽，原账号被排除后仍固定原归属 | `session_retry_failover.go` 共用正常迁移事务；只有端点允许重试且具有失败证据才迁移 |
| Messages 请求内重试 | 没有挂载会话重试状态 | `/v1/messages` 与 Responses/Chat/compact/WS 共用会话换号状态 |
| Chat / Messages 回放校验 | 校验器只看 `input`，原始 `messages` 被当成空上下文 | 仅转换校验副本的输入，保留入站身份和 metadata；实际发送仍由各端点正常翻译 |
| 选号前后模型/健康状态变化 | 准备后再发生拒绝，没有重新准备迁移 | 选号失败后重新检查当前归属；成功提交后清除原账号的模型拒绝标记，保留过滤器 |
| 候选数固定为 16 | 前 16 个候选在身份/容量准备时失败，后续可用账号不再尝试 | 按当前账号池大小设置有限上界，每次排除已试候选并检查取消 |
| 已检查方案的失败被忽略 | `Checked` 后可能退回普通选号，掩盖事务失败 | 已失败方案保持终态，返回明确错误，不能继续使用过期归属 |
| 候选暂时不可用 / 归属存储故障 | 返回 400、不可重试或要求新建窗口 | 返回 503 与可重试提示；完整上下文缺失仍返回 400，不放行不完整回放 |

## 保留的阻断和策略

| 层次 | 条件 | 原因 / 处理 |
| --- | --- | --- |
| 启用方式 | 自动换号和宽松模式都关闭 | 不做持久迁移；已有迁移记录仍恢复当前归属 |
| API Key | 目标的分组、套餐、渠道或显式授权不允许 | 目标仍不可选，提交前再次核验；宽松只放开原账号与目标的同组约束 |
| 非宽松模式分组 | 目标分组集合不同 | 保留显式严格策略，诊断 `account_groups_mismatch`；标签不参与筛选 |
| 身份来源 | 根冲突、匿名/无法关联的被动请求、伪造签名 | 不凭请求字段接管其他用户的会话；无稳定根的请求使用原有独立调度 |
| 原账号缺失 | 无法恢复原账号或其元数据 | 宽松模式走既有 missing-owner 恢复；存储错误不能冒充“账号不存在” |
| 窗口 | 非法/冲突标识、强制连续性、无法验证授权票 | 不能越过窗口权益或所属关系；宽松 off/observe 的缺失窗口沿用已有延期建立规则 |
| 用户与 Key 限额 | 用户窗口/扩容权益、Key/scope 预算或请求并发用尽 | 换账号不能绕过用户级限额 |
| 账号瞬时请求并发 | 请求槽或共享并发暂满 | 保留调度等待及相关后台专用额度；不把短暂忙碌直接当成持久账号失效 |
| 候选账号 | 模型、路径、冷却、出口、会话容量、身份映射不可用 | 继续检查下一候选，记录淘汰原因；池用尽返回 503 |
| 路径 | 已使用 BPS 的历史试图返回 native | 保留单向边界；native → BPS 也必须通过归属事务 |
| 跨账号上下文 | 仅剩不可迁移引用、无完整可重放输入、工具对断裂 | 清理/保留模式分别检查，拒绝缺失上下文；不能仅换 UUID 就发送旧引用 |
| 请求内重试 | 已输出、预算耗尽、请求取消、明确禁止重放、参数/策略拒绝 | 端点先决定是否可重试；本次没有新增无限重试或跳过端点预算 |
| sticky 策略 | 临时故障明确配置同账号重试，未排除原账号 | 保留该策略；rotate 下有失败证据的排除可触发持久换号 |
| 后台归属 | 父账号/代数在等待或发出前改变 | 不发送过期身份；符合宽松授权的后台请求可用请求私有段，不迁移父根 |
| 提交竞争 | 持久 owner/generation CAS 失败、分组/Key 授权变化 | 不覆盖另一个请求已提交的归属；释放候选槽并返回明确诊断 |
| relay | 原生中转协议请求 | 使用原有 relay 亲和/协议策略，不套用 Codex 跨账号身份事务 |

## 可验证证据

- `TestSessionFailoverOwnerRejectionMatrix`：普通自动换号与宽松模式，模型、路径、401、付款、错误、凭据、普通及模型冷却。
- `TestSessionDispatchFailureUsesSchedulerState`：共享冷却、共享模型冷却、Key 授权、不可用出口、次数上限、lazy 凭据、额度豁免。
- `TestSessionFailoverAcrossIngressProtocols`：先建立真实旧会话，再在 Responses、compact、Chat、Messages、WebSocket 发出请求，分别验证模型变化与临时 429 后实际更换上游账号。
- `TestSessionFailoverSearchesBeyondSixteenCandidates`：前 16 次身份准备失败，第 17 次成功。
- `TestSessionFailoverRechecksOwnerAfterSelectionFailure`：准备后模型发生变化，仍能迁移。
- `TestCommittedSessionOwnerClearsOnlyPreviousDenial`：迁移后清除旧拒绝而不移除模型约束。
- 继续运行已有 exact-groups、Key 授权、窗口、missing owner、后台、fork、quota/sticky、工具上下文、输入保留、归属竞争、WS 身份隔离和 BPS 轮次/图片冷却测试。

没有新增默认开关、修改账号配置或调整首字统计。本次检查的是本地代码和受控上游测试；部署后仍应以 `account_failover.trigger_reason`、`block_reason`、候选淘汰详情和实际上游结果判断个案。
