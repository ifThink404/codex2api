# Prompt 审计筛选与本地执行策略

状态：四项功能已实现。

## 日志排序与分类搜索

位置：Prompt 检查 → 触发日志 → 本地过滤与异步审计日志。

- 排序支持时间最新（默认）、审计分从高到低、审计分从低到高。后端对全部筛选结果排序后分页，同分按时间、ID 倒序。
- 关键词旁的下拉框支持全部、NewAPI 用户名、内容、命中规则、错误／审查原因、API Key。
- 用户名使用已验证的 NewAPI 平台和用户 ID 关联身份表，按当前已保存的用户名模糊查询；不会误查其他平台的同号用户，也不会同时匹配正文或 Key 名称。
- 搜索中的 `%`、`_` 按普通字符处理。改变条件后点击“应用筛选”（关键词框也支持回车）回到第一页，重置恢复默认。
- 已有日志可利用已有身份关联查询。若历史日志及身份记录从未保存用户名，则无法凭用户 ID 还原姓名；后续已验证日志会更新关联，纯影子记录也会保存身份但不新增风险事件。

## 本地规则处理方式

位置：Prompt 高级配置 → 展开专家设置 → 高级可视化配置顶部。

保存字段：`enforcement.local_mode`，位于原有 `prompt_filter_advanced_config` JSON 中，默认 `block`（保留原行为）。

| 值 | 本地动作 | 模型复核 |
| --- | --- | --- |
| `block` | 保留原规则警告／拦截 | 按现有配置处理 |
| `monitor` | 记录命中，放行；本地分计入审计分 | 仍可独立拦截 |
| `warn` | 记录并警告，HTTP 使用现有警告头 | 仍可独立拦截 |

- 本地动作在外部模型复核之前单独降级，保留原始动作供“仅复核本地拦截／候选”的范围判断。
- 模型违规结论、复核失败时的 fail-closed／fail-open 策略保持独立；仅警告产生的本地警告不会被模型通过抹掉。
- 全局执行模式仍限制最终动作。要“本地仅监控但模型正常拦截”，全局应允许执行，本地选择仅监控。
- 本地仅监控／仅警告不新增本地会话锁或用户 strike；已有锁、上游安全事件等独立限制不被解除。
- HTTP、WS、后台管理图片检查和已有输出规则均遵守本地处理方式；WS 不插入不兼容的警告事件。

## 辅助内容高置信拦截

同一位置新增开关，保存字段 `enforcement.auxiliary_high_confidence_enabled`，**默认 false**。缺失字段按关闭处理，旧配置不自动开启。

开启后，已启用检查的辅助来源在转送上游前同步检查。Developer、System、Instructions、工具输出／参数、独立历史段、附件引用／内容和会话上下文均可适用；来源层关闭时不检查。来源层的独立设置和档案继承方式仍有效。

### 拦截依据

必须同时满足：

1. 来源适用、开关开启，且当前段未被截断、未超过辅助扫描预算。
2. 同一段内容命中至少一条非 SignalOnly 的 strict 高置信规则，其权重至少达到当前拦截阈值。
3. 经现有意图识别、上下文排除和降分后，仍具有明确敏感操作意图、严格规则证据及达到阈值的有效分。
4. 检测未报告编码还原扫描不完整。

不直接使用影子审计分，也不把不同工具输出或不同历史段的关键词相加形成候选。仅出现“PowerShell”“许可证破解”等词不满足条件；是否构成操作请求必须由规则与上下文共同判断。客户端声称已授权不自动构成豁免。

候选遵守本地处理方式及全局模式：只有两者都允许拦截时才阻断。辅助来源归属不改为用户输入，不将辅助命中作为用户终局或处罚证据，不新增对话锁、strike 或封号。

需要模型复核时使用实际命中段；模型通过不会抹掉拦截模式下已确认的辅助高置信候选。本地仅监控／仅警告时，模型保持独立判定。已识别的应用内部候选与原有明确关联用户历史的处理边界保持原样。

原有工具输出高置信复合指令拦截是独立的兼容路径。新开关关闭不取消它；该旧路径也遵守新本地处理方式，并排除用户处罚。

## 诊断与兼容

- 日志仍分别展示执行分与审计分、来源层和命中内容；本地监控分不冒充执行分。
- `local_rules_monitor` / `local_rules_warn` 表明本地候选降级；`external_review_local_monitor` / `external_review_local_warn` 表明模型在本地非拦截模式下作出最终限制。页面显示本地模式标签，并将后者归为模型决策来源。
- Guard 决策中的 `auxiliary_high_confidence` 标记新的辅助高置信候选；Verdict 保留 `local_mode`、`local_original_action`、`local_action` 供测试／诊断。
- 均衡／严格的主要差异是继承来源层的默认审计范围；显式来源层配置优先，严格不自动降低阈值或跳过模型复核。

## 验证范围

覆盖后端排序和分页、用户名范围及特殊字符搜索、接口参数白名单、旧配置默认值与序列化重载、本地三种模式和模型通过／违规／失败组合、HTTP／WS、辅助来源开启／关闭、分散证据、截断、普通关键词、防御说明，以及辅助拦截不产生处罚证据。前端执行类型检查与生产构建。
