# 宽松换号：缺失窗口与旧绑定恢复

宽松模式开启后，原账号因禁用、暂停、额度、容量或 `payment_required` 不可用时，以下两类请求可以继续走正常换号流程：

- 请求未提供窗口编号，连续性模式为关闭或观察：保留未知编号，迁移时只建立新的账号代次；首次收到真实窗口时才从出站窗口 0 开始编号。不往请求中伪造入站窗口编号。
- 当前作用域已有有效的账号绑定或已验证窗口授权，但缺少连续性数据库记录：重新核对绑定，事务补存同一个原账号，再执行原有按账号和代次比较的换号事务。历史路径不可恢复时，支持 BPS 的原账号使用保守的 BPS 下限，避免错误退回 native。

正式连续性校验、已有账号归属冲突、数据库错误、异常窗口格式、工具配对及请求上下文检查仍生效。没有可核实的原绑定时不会凭客户端字段创建账号归属。完整保留 input 的开关语义不变；未开启时仍使用既有上下文清理流程。

管理员错误日志的 `account_failover.continuity` 新增：连续性模式与检查结果、窗口缺失/异常原因、窗口编号是否已知、归属来源、当时数据库中的账号 ID、旧绑定恢复结果、是否延迟建立出站窗口。缺少持久化记录时不再直接把上一条上游路径记成 `native`。这些字段不含原始会话标识或请求内容。

## 原账号不在运行池

宽松模式将此情况纳入 `account_missing` 换号。数据库仍有正常账号时先重新加载；不会重新激活回收站账号。已删除、已彻底移除、或明确缺失 Codex 凭据时，以原账号 ID 和当前持久化代次执行同一换号事务，不再依赖原运行时对象存在。

宽松模式下，无论原账号是否仍有分组记录，均不要求候选与旧账号的分组一致，但始终执行 Key 分组权限筛选。日志标记 `selection.match_mode=relaxed_key_scope`。显式账号许可、模型、套餐、渠道、已知的 BPS 路径下限、上下文清理/完整保留、窗口授权、容量及账号代次校验保持不变。提交前再次检查原账号状态、凭据代次和上游身份；仅分组变化不阻止迁移，但目标若因此失去 Key 授权则不能提交；查询失败仍不视为账号已删除。

`account_failover.owner_lookup` 区分 `not_found`、`deleted`、`credentials_missing`、`reloaded`、`lookup_failed`、`reload_failed` 以及提交前的 `recheck_*`。恢复账号后不换号时，结果为 `owner_reloaded`；没有合格替代账号时仍记录 `no_safe_candidate` 和候选淘汰原因。
