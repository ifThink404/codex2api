# 多个 NewAPI 的审核绑定与用户隔离

当前每把 Codex2API API Key 对应一个审核绑定，其中配置平台标识和签名密钥。签名密钥用于验签，不作为 NewAPI 实例身份；不能依靠相同用户 ID 的来源 IP、访问域名或 UA 自动区分不同 NewAPI。

| 范围 | 当前隔离依据 |
| --- | --- |
| 已验证用户、BPS 用户提问计数、用户级响应引用归属 | Codex2API API Key ID＋审核绑定平台标识＋NewAPI 用户 ID |
| 连接所有者 | 上述范围＋已签名渠道 ID＋NewAPI Token ID |
| 短期会话／风控状态 | API Key＋平台＋已签名渠道，再按相应会话／用户标识分区 |
| 请求重放检查 | API Key＋平台＋请求 ID |
| 持久化审核用户记录与用户冷却 | 平台标识＋NewAPI 用户 ID |

多个独立 NewAPI 共用同一把 API Key、同一审核绑定时，即便来自不同地址，相同用户 ID 仍被视为同一用户范围；渠道 ID 不同只能分开部分状态。请求 ID 相同还可能触发重放拒绝。若请求里的平台标识不匹配该 Key 的绑定，验签流程不会接受为另一平台。

当前配置方式应为每个独立 NewAPI 创建独立的 Codex2API API Key 和不同的平台标识，例如 `newapi-a`、`newapi-b`。此时用户 ID、Token ID、渠道 ID和请求 ID 相同也能按各自绑定隔离。验签可以使用相同的签名密钥，但密钥本身不能替代 Key 和平台边界；账号分组及分流规则仍由各 API Key 配置决定。

若确需多个 NewAPI 共享一把 API Key，需另行增加受验签保护的实例标识，并贯穿用户计数、会话归属、缓存、审核和重放检查。当前版本没有自动补充这一实例维度。

验证覆盖：同 Key／平台但不同来源地址、不同渠道、独立 Key／平台且相同用户／Token／渠道／请求 ID、重复请求拒绝及平台不匹配拒绝。使用本地测试请求，不向真实上游发送。
